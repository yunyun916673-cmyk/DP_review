# 跳躍島嶼
## 題目意思
有一名冒險者想要穿過一片漂浮在空中的神秘群島，群島共有 N 座島嶼排成一列，每座島嶼都有一個高度值。冒險者目前位在第 1 座島嶼，目的地是第 N 座島嶼。他每次可以選擇往前跳 1 座島嶼或 2 座島嶼。每次跳躍消耗的體力為兩座島嶼高度差的絕對值。請幫助冒險者計算出，到達終點所需要消耗的最小體力總和。

## 輸入格式
第一行包含一個正整數 T，代表共有 T 筆測試資料。
對於每筆測試資料：
第一行包含一個正整數 N，代表島嶼的數量。
第二行包含 N 個整數，依序代表第 1 座到第 N 座島嶼的高度。

## 輸出格式
對於每筆測試資料，請輸出一行包含一個整數，代表到達第 N 座島嶼的最小體力消耗。

## 範圍限制
T <= 10
1 <= N <= 100000
島嶼高度 <= 1000000

# 跳躍島嶼
## 題目想法
這題本質上是經典「爬樓梯問題」的進階轉換。要抵達目前的所在位置，情況非常單純，只可能有兩種來源：第一種是從前一步（跨一格）過來，第二種則是從前兩步（跨兩格）過來。

## 解題過程
利用動態規劃來紀錄抵達每一個位置的最小成本。首先將起點 dp[1] 的成本設為 0，並將其他尚未計算的位置初始化為極大值（INF）。接著透過迴圈從第 2 個位置開始依序往後推算，每次都比較「走一步」與「走兩步」所花費的體力差，取兩者的最小值更新到當前位置的 dp 陣列中。

## 解題方法思考
因為抵達第 i 個位置的狀態只能從 i-1 或 i-2 轉移而來，所以狀態轉移方程式非常明確：
dp[i] = min(dp[i-1] + abs(A[i-1] - A[i]), dp[i-2] + abs(A[i-2] - A[i]))
為了避免多筆測試資料造成的陣列殘留或全域變數汙染問題，實作上特別使用了 struct DP 將每筆測資的變數及運算邏輯獨立封裝，讓整體架構更加乾淨。

## 複雜度分析
### 時間複雜度：O(N)
每一筆測試資料只需要對陣列進行一次線性掃描，且狀態轉移的計算為 O(1)。若共有 T 筆測資，總時間為 O(T * N)。

### 空間複雜度：O(N)
使用了長度為 N+1 的陣列來儲存高度資料與 DP 狀態表。

## 學習心得
透過這題更加熟悉了基礎的一維動態規劃模型。將看似複雜的體力消耗問題，看透並化簡為熟悉的爬樓梯邏輯，能大幅降低思考的難度。同時，透過 struct 封裝測資的撰寫風格，不僅讓 main 函式更加簡潔，也讓程式碼的重用性與安全性提升不少，是未來面對 APCS 或是各種演算法競賽時非常值得繼續保持的良好習慣。
