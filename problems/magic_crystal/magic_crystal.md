# 魔法水晶
## 題目意思
魔法學徒正在煉金工坊中調配魔藥，他需要剛好湊齊 P 點魔力值。工坊裡有 N 種不同魔力容量的無限量魔法水晶。學徒想知道，總共有多少種不同的水晶組合方式，可以剛好湊出 P 點魔力值。

## 輸入格式
輸入包含多筆測試資料。
每筆測資第一行有兩個正整數 N 與 P。
接下來會有 N 個正整數，代表每種魔法水晶所蘊含的魔力值。
當 N=0 且 P=0 時代表輸入結束。

## 輸出格式
對於每筆測試資料，輸出一行整數，代表可以湊出剛好 P 點魔力的組合總數。

## 範圍限制
N <= 50

P <= 100000

答案保證在 64-bit 有號整數 (long long) 範圍內。

# 魔法水晶
## 題目想法
這一題雖然經過了故事背景的包裝，但仔細分析其核心邏輯，就會發現它本質上是一個標準的「完全背包問題」（求組合數）。我們需要用給定的無限量物品（水晶／硬幣），湊出特定的總和，並計算共有多少種組合方式。

## 解題過程
由於每種物品的數量是無限的，因此在實作動態規劃時，內層迴圈必須是「由小到大」正向走訪，這與 0/1 背包問題的逆向走訪不同。我們將初始狀態 dp[0] 設為 1（代表湊出總和為 0 的方法數為 1 種，即什麼都不拿），接著逐一加入不同種類的物品，並累加每種面額可以湊出的方法數。

## 解題方法思考
解題主要採用一維動態規劃（1D DP）。
狀態轉移方程式為：dp[j] += dp[j - K[i]]。

防止溢位：組合數量可能會非常龐大，所以必須全線使用 long long（包含常數後綴 0LL 與 1LL）來確保加法過程不會溢位。

## 複雜度分析
### 時間複雜度：O(N * P)。
外層迴圈遍歷 N 種物品，內層迴圈最多遍歷 P 個容量狀態，整體時間為兩者相乘。

### 空間複雜度：O(P)。
經過狀態壓縮後，僅需使用一個一維陣列 dp 來記錄大小為 P 的狀態。

## 學習心得
透過這題更加鞏固了完全背包問題的解題模板與內層迴圈正向遍歷的設計概念。同時也再次驗證，利用 struct 封裝多筆測資邏輯是一個非常好的實作習慣，不僅提升了程式碼的可讀性，更能徹底根除變數未初始化造成的隱蔽 Bug，未來可以繼續將這個架構應用在其他 DP 題目上。
