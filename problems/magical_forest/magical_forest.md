# 奇幻森林
## 題目意思
在一個古老的王國中，有一座由 n 個神聖祭壇組成的森林，祭壇編號從 0 到 n-1，且彼此以樹狀結構相連。
其中 0 號祭壇是整座森林的根源聖殿。每個祭壇都被賦予了一種神聖的色彩，分為白色與黑色。
為了進行一場神聖的儀式，王國的守護者需要切斷森林中的某些連結（邊）。當切斷若幹條邊後，整座森林會被分割成多個獨立的聖域連通塊。
守護者希望每一塊獨立的聖域連通塊內部，剛好包含且僅包含一個白色祭壇。請計算共有多少種不同的邊切斷方案，能完美達成這個條件。
因為方案可能非常龐大，請輸出答案對 1000000007 取模後的結果。若兩個方案所刪除的邊集合不同，則被視為不同的方案。
## 輸入格式
第一行包含一個正整数 n，表示森林中祭壇的總數量。
第二行包含 n-1 個數字，第 i 個數字表示第 i 個祭壇的父節點編號（根節點為 0 號，且父節點編號小於 i）。
第三行包含 n 個數字，第 i 個數字表示第 i-1 個祭壇的顏色，其中 0 表示白色，1 表示黑色。
## 輸出格式
輸出一個整數，表示滿足條件的切邊方案數對 1000000007 取模後的結果。
## 範圍限制
1 <= n <= 10^5

# 奇幻森林
## 題目想法
這道題目一開始最讓人卡關的地方，在於我們心裡想的是「要刪除哪些邊的組合」，但樹形 DP 的核心卻是在處理「子樹的合併與保留」。
對於整棵樹而言，每切斷一條邊就會把樹分成兩部分，而題目要求的條件是：每一個連通塊內「剛好包含一個白色結點」。
這意味著我們在由下往上進行樹形 DP 時，可以將問題轉化為：對於每個子樹，我們考慮它與其父節點之間的這條邊「要不要切斷」。
如果切斷，這棵子樹就會形成一個獨立的連通塊，必須確保這個子樹內部剛好包含一個白色結點才合法；如果不切斷，它就會和父節點合併成同一個連通塊。
這種透過決定每條邊「切」或「不切」來組合出不同刪邊集合的視角，是這類樹上子樹合併問題的關鍵。
解題過程
在解題的實作上，我們採用由下往上的 DFS 走訪順序（類似後序走訪 Post-order traversal），從葉子節點一路往根節點計算。對於當前處理的節點 pwd：
初始化狀態：先根據當前節點本身的顏色（白色或黑色）來初始化 DP 陣列。若為白色，則初始時當前連通塊包含 1 個白點；若為黑色，則包含 0 個白點。
子樹迭代合併：對於當前結點的每一個子節點 nxt，我們遞迴處理該子樹，然後將子樹的狀態合併到當前結點中。
假設我們目前已經處理了前 x 條子樹，現在要納入第 x + 1 條子樹（即節點 nxt 及其與當前結點之間的邊），這裡就對應到「保留該邊（合併）」或「切斷該邊（獨立形成合法連通塊）」兩種選擇的狀態轉移。
狀態轉移與模數維護：在合併過程中，利用乘法原理將子樹中切邊與不切邊的方案數相乘，並在每一步取模以防止數值溢位。
最後整棵樹的答案就會收斂在根節點 0 的合法狀態上。
## 解題方法
定義 dp[pwd][0] 表示以 pwd 為根的子樹中，當前所在的連通塊內沒有白色結點的方案數；
dp[pwd][1] 表示當前所在的連通塊內恰好有 1 個白色結點的方案數。轉移邏輯：當我們把子樹 nxt 合併到 pwd 時：
如果切斷 pwd 與 nxt 之間的邊，那麼子樹 nxt 必須是一個合法的獨立連通塊（即內部恰好有 1 個白點，對應 dp[nxt][1]），這會使總方案數乘上 dp[nxt][1]。
如果不切斷這條邊，則子樹 nxt 會和 pwd 合併，此時可以選擇子樹 nxt 內部不含白點（dp[nxt][0]）或剛好含 1 個白點但不與其他部分衝突的情況進行組合。
這種「逐個子樹加入並滾動更新狀態」的背包式合併手法，保證了我們在處理到第 x + 1 條子樹時，前面 $x$ 條子樹的累積狀態已經完備。
## 複雜度分析
### 時間複雜度：O(n)。
每個節點和每條邊在 DFS 過程中剛好被訪問一次，子樹合併的狀態大小固定為 2 種（有白點或無白點），因此總運算次數與節點數 n 成線性關係，能輕鬆通過 n<=10^5 的測資。
### 空間複雜度：O(n)。
主要消耗在儲存樹結構的鄰接表 ship、顏色陣列 color 以及大小為 2n 的 dp 陣列。
## 學習心得
透過這道題，我深刻體會到樹形 DP 中「邊的刪減與子樹合併」的對應關係。
一開始會糾結於「刪除邊集合不同」的定義，但實際上只要把決關點放在「每一條邊要不要切斷」，並用狀態來維護連通塊內的條件限制（如本題要求的「恰好一個白點」），問題就會變得非常有條理。
特別是透過模擬「處理了 x 條子樹、準備處理第 x+1 條子樹」的增量合併過程，讓我對樹上背包與子樹狀態轉移的本質有了更清晰的理解，也為未來處理更複雜的樹狀結構剪裁問題打下了很好的基礎。
