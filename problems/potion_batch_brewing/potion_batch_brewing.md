# 魔法藥水批次釀造
## 題目意思
在一個神祕的魔法工坊裡，煉金術士需要依序調製 N 種不同的魔法藥水。每種藥水有其指定的優先順序 p_i、所需容量 s_i 以及凝固時間 t_i。
工坊的魔導鍋容量上限為 Q。煉金術士必須先將所有藥水依照優先順序由小到大排序。接著，他可以把連續的藥水組合成一個批次放入魔導鍋中一起釀造。
容量限制：同一個批次中所有藥水的容量總和不能超過魔導鍋的容量上限 Q。凝固時間：一個批次所需的總凝固時間，等於該批次中所有藥水凝固時間的最大值。一旦批次放入後便無法中途加入或取出。
請幫煉金術士計算出在所有合法的分批方式中，釀造完所有藥水所需的最短總時間。
## 輸入格式
輸入第一列包含兩個正整數 $Q$ 和 $N$，分別代表魔導鍋容量上限與藥水總數。接下來的 N 列中，每列包含三個正整數 p_i、s_i 和 t_i，分別代表每種藥水的優先順序、容量與凝固時間。
保證所有 $p_i$ 值均相異。
## 輸出格式
請輸出一個整數，代表釀造完所有藥水所需的最小總時間。
## 範圍限制
第一子題組：N <= Q，所有 s_i = 1。
第二子題組：所有 t_i = 1。
第三子題組：無特殊限制。

# 魔法藥水批次釀造
## 題目想法
這一題其實就是一個動態規劃（DP），而它在儲存的狀態就是題目所要的答案，也就是最短時間。
由於題目要求必須先依優先順序排序，接著將連續的藥水進行分批，這非常適合用一維 DP 來記錄將前 i 個藥水完全釀造完畢所需的最小總時間。
## 解題過程
資料預處理：讀入所有藥水的優先順序 p_i、容量 s_i 與凝固時間 t_i，並依照優先順序 p_i 由小到大進行排序。
狀態定義：定義 dp[i] 為前 i 種藥水完成釀造的最短總時間。狀態轉移與枚舉：對於每一個位置 i，我們向回枚舉前一個批次的起點 j，嘗試將從 j 到 i 的藥水結合成同一個批次。
合法性檢查：在內層迴圈中，累積容量小於等於容量上限 $Q$，並維護該批次中最大的凝固時間，利用前一個狀態 $dp[j-1]$ 加上當前批次時間來更新 $dp[i]$ 的最小值。
## 解題方法思考
因為本題的資料規模 N 很小（N <= 16 等限制），所以可以直接採用 O(N^2) 的暴力枚舉法來尋找最佳分批點。
透過內層迴圈往回累加容量並計算最大凝固時間，能夠完整涵蓋所有合法的連續分批組合，邏輯直觀且實作上不易出錯。
## 複雜度分析
### 時間複雜度：O(N^2)。
外層迴圈執行 N 次，內層迴圈最多往回執行 N 次，在 N 較小的範圍內運算速度極快，能輕鬆通過所有測資。
### 空間複雜度：O(N)。
使用一維陣列儲存 DP 狀態及結構體儲存藥水資訊，記憶體消耗極低。
## 學習心得
這題讓我熟悉了結合排序與動態規劃的分批最佳化問題。當看到題目要求將序列分割成若干個合法區間以求極值時，可以聯想到透過記錄前項最佳解來轉移。
同時也體會到，在資料範圍允許的情況下，利用 O(N^2) 的枚舉來處理區間合併是一種非常穩健且高效的思考方向。
