# 港都海鮮拍賣會的組合優惠策略

## 題目想法
本題表面上提供了三種不同的促銷規則與多種組合模式（M = 0 到 6），看似條件繁雜，但核心本質其實是「排序後的線性動態規劃（DP）」。
為了讓「買二送一」或「買三送二」的折抵效益最大化，直覺上應該將價格相近的高價商品綁在一起結帳，因此第一步必須先將所有商品價格由大到小排序。排序後，所有的組合優惠都會落在連續的區間上，問題就能轉化為標準的一維 DP 狀態轉移。

## 解題過程
1. **分治拆解子任務**：針對不同的模式代號 M，先將單一優惠規則（如僅套用買二送一或買三送二）直接用排序後的貪心取餘數計算，確保基礎邏輯無誤；再針對複合優惠模式（M = 4, 5, 6）設計動態規劃。
2. **設計 DP 狀態與轉移**：定義 `dp[i]` 為買下排序後前 `i` 件商品的最低總花費。對於第 `i` 件商品，考慮以下幾種決策轉移：
   - 單買原價：`dp[i - 1] + price[i]`
   - 單買打折（若包含方案 C）：`dp[i - 1] + price[i] * (100 - P) / 100`
   - 買二送一（若包含方案 A 且 i >= 3）：`dp[i - 3] + price[i - 2] + price[i - 1]`
   - 買三送二（若包含方案 B 且 i >= 5）：`dp[i - 5] + price[i - 4] + price[i - 3] + price[i - 2]`
3. **處理浮點數與進位問題**：由於打折會產生小數點後兩位，且最終結果需無條件進位，實作時決定放棄浮點數型別，改以整數放大倍率來維持絕對精度。

## 解題方法思考
本題最關鍵的實作技巧在於「浮點數的整數化處理」。由於折扣百分比 P 是整數，每個商品打折後的價格最多只會出現小數點後兩位（即除以 100）。如果直接使用 `double` 進行累加與取最小值，在資料量高達 200,000 筆時極易產生浮點數精度誤差，導致最後無條件進位時出錯。
透過在讀入資料時先將所有價格乘上 100，所有的加減與折扣運算都能在 `long long` 整數域內精確完成，最後輸出前再透過 `(dp[N] + 99) / 100` 進行整數無條件進位，完美避開了浮點數陷阱。

## 複雜度分析
- **時間複雜度**：O(N log N)。主要時間花費在將 N 件商品由大到小排序（O(N log N)），後續線性動態規劃轉移僅需掃描一次陣列（O(N)）。
- **空間複雜度**：O(N)。需要額外開闢大小為 N 的陣列來儲存商品價格與 `dp` 狀態表。

## 學習心得
這題雖然題面敘述看起來規則很多、情況複雜，但只要冷靜把問題拆解並抓出「排序後具備區間連續性」的特質，就能回歸到非常標準的線性 DP 求解。此外，這次在處理小數折扣與無條件進位時，體會到「將小數放大轉為純整數運算」的威力，不僅寫法乾淨，也徹底杜絕了浮點數誤差帶來的風險，對未來處理涉及金額或百分比的題目很有啟發。
