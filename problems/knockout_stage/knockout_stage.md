# 淘汰賽
## 題目意思
在元素王國的年度魔法學院大賽中，共有 N 位年輕的魔法學員站成一個巨大的圓形陣列，編號依序為 1 到 N。
大賽規則如下：每位學員初始時擁有一定的生命能量值 K。從編號 1 的學員開始，以固定的步伐數 S 進行順時針報數。當數到第 S 個人時，該學員的生命能量值會扣減 1 點。
若該學員的生命能量值歸零，則該學員會被淘汰並離開陣列（後續報數時直接跳過已淘汰的人）。遊戲持續進行，直到場上只剩下最後一位學員（即總共被淘汰了 N-1 個人）為止。
請幫助主辦單位計算出，最後留在場上的優勝學員編號是幾號？
## 輸入格式
第一行包含三個正整數 N, S, K，分別代表學員總人數、報數步伐數、以及每位學員的初始生命能量值。1 <= N <= 2 *10^51 <= S <= 10^91 <= K <= 10^9
## 輸出格式
輸出一個正整數，代表最終獲勝的學員編號。
## 範圍限制
時間限制：1.0 秒記憶體限制：256 MB

# 淘汰賽
## 題目想法
這題表面上是經典的約瑟夫環（Josephus Problem）模擬，但加入了兩個複雜的挑戰：第一是每個人擁有獨立的初始生命能量值 K，必須被淘汰多次（扣減 K 次）才會真正出局。
第二是人數規模 $N$ 高達 2*10^5，且步伐數 S 可達到 10^9。如果使用傳統的暴力模擬或是普通的串列，每次尋找下一個淘汰目標的複雜度會是 O(N)，
總時間複雜度將會惡化至 O(NS) 或 O(N^2)，無法在 1.0 秒內通過。因此，必須引入能夠高效支援「動態維護元素存在狀態」與「尋找第 x 個存活者」的資料結構。
## 解題過程
資料結構選擇：為了在 O(log N) 時間內同時支援「單點更新（人員淘汰）」與「前綴和查詢」，我們採用樹狀陣列（Binary Indexed Tree, BIT）。
動態二分搜定位（find_xth）：藉由 BIT 的區間特性，我們可以在 O(log N) 的時間內，透過倍增法（類似二分搜的技巧）找出當前還活著的人當中，第 pos 個人實際在陣列中的實體編號。
數學取模優化：當前還活著的總人數 sz 會隨著淘汰人數增加而減少。每次要數 S 個步伐時，可以直接利用取模運算 pos = (pos + S - 2) % sz + 1 來大幅跨越已經淘汰的空缺，避免不必要的逐個計數。
生命值扣減與淘汰：每次定位到目標學員後，將其生命值 alived[st] 減 1。若歸零，則透過 BIT 將該位置的值從 1 改為 0（代表從存活名單中移除），並讓已淘汰人數 killed 加 1。
## 解題方法思考
空間與時間的平衡：使用 BIT 維護存活狀態，將每一次查詢和更新壓到 O(log N)。
指標對齊與 1-based indexing：在約瑟夫環的位移計算中，由於每次淘汰後陣列大小會動態改變，必須精準處理環狀指標的位移，確保 (pos + S - 2) % sz + 1 的位移基底不會產生負數或索引錯位。
最終掃描：當 killed == N - 1 時，迴圈結束，最後線性掃描一次 alived 陣列找出那個生命值大於 0 的唯一倖存者即為答案。
## 複雜度分析
### 時間複雜度：
初始化 BIT 需要 O(N)。每次淘汰一人需要進行一次 find_xth 查詢與一次 update 修改，兩者皆為 O(log N)。總共需進行 N-1 次淘汰，
因此總時間複雜度為 O(N log N)，在 N = 2*10^5 時可在約 0.1 秒內輕鬆完成。
### 空間複雜度：
需要儲存 BIT 陣列、生命值陣列 alived，大小皆為 O(N)。總空間複雜度為 O(N)，遠低於 256 MB 的限制。
## 學習心得
透過這題我深刻體會到，當經典的模擬問題結合了大範圍的數據限制時，暴力解法往往會失效。
將「約瑟夫環」與「樹狀陣列（BIT）」結合，並利用類似線段樹的倍增二分搜技巧在 BIT 上尋找第 k 個元素（find_xth），是解決動態刪除與排名問題的經典利器。
這不僅強化了我對資料結構底層操作的理解，也提升了面對複雜指標跳躍與取模運算時的程式碼穩健度。
