# 優惠
## 題目意思
在觀光老街上有一家歷史悠久的手工醬油鋪，老闆為了回饋老主顧，發放了一張面額為 m 元的特惠抵用券。這張抵用券可以用來購買店內的各種醬料與特色伴手禮，但使用時必須遵守以下規定：
每張抵用券只能使用一次，且挑選的商品總金額必須大於或等於 m 才能折抵。商品總價如果超過 m 元的部分，顧客需要額外補差價結帳。
每種商品在同一次結帳中只能買一個。舉例來說，假設抵用券面額為 100 元，店內有 5 種商品，價格依序為 52、36、79、51、36 元。
如果選擇購買商品 1、2、3，總價為 52 + 36 + 79 = 167 元，扣除 100 元抵用券後，還需補繳 67 元。如果選擇購買商品 1、4，總價為 52 + 51 = 103 元，扣除 100 元抵用券後，只需要補繳 3 元。
請寫一個程式，協助顧客挑選商品組合，讓總金額大於或等於 m 的前提下，使顧客需要額外補繳的現金金額降到最低。
## 輸入格式
輸入資料包含兩列。
第一列有兩個正整數 m (m <= 900000) 與 $n$ (n <= 100)，分別代表抵用券面額與店內商品種類數。
第二列有 $n$ 個正整數 p_1, p_2, ... , p_n (0 < p_i <= 1000000)，依序代表第 1 至第 n 個商品的價格。
輸入保證 m < p_1 + p_2 + ... + p_n。
## 輸出格式
請輸出使用抵用券購買商品時，顧客所需額外補繳的最小金額。
## 範圍限制
第一子題組 [25 分]，商品數量 n 介於 2 到 9 之間 (2 <= n < 10)。
第二子題組 [26 分]，商品數量 n 介於 10 到 19 之間 (10 <= n < 20)。
第三子題組 [49 分]，商品數量 n 介於 20 到 100 之間 (20 <= n <= 100)。

# 優惠
## 題目想法
看到這題需要從 n 種商品中挑選不同的組合，使得總金額大於或等於目標面額 m 且超過的部分越少越好，這立刻讓人回憶起經典的子集和（Subset Sum）與背包問題概念。
我們需要找出所有可能透過挑選商品所湊出來的數值組合，並從中找出最接近且大於等於 m 的合法解。解題過程狀態轉移設計：
起初思考時，可以利用動態規劃來記錄哪些金額是可以被湊出來的。為了優化空間與時間，可以透過滾動陣列或是 C++ 的 bitset 來進行狀態壓縮。
優化與剪枝：當某個商品的價格本身就已經大於或等於 $m$ 時，可以直接拿來與當前最優解比較。位元平行加速：利用 bitset<1800005>，將所有可以湊出的金額狀態存放在位元中。
透過 dp |= (dp << cnt) 的位元運算，能夠同時平行的更新所有狀態，大幅省去傳統迴圈的開銷。
尋找答案：最後在總金額從 m 到 2m 的區間內，尋找第一個 dp 值為 true 的合法總金額，將其減去 m 即為所求的最少補繳金額。
## 解題方法思考
本題的核心在於「求所有數值組合」的效率瓶頸突破。當商品數量 n <= 100 且目標金額 m <+ 900000 時，如果用一般的 DP 迴圈可能會面臨效能壓力。
而 bitset 巧妙地利用了硬體層級的 64 位元平行運算，將原本 O(n*m) 的迴圈常數除以 64，使程式碼既簡潔又具備極高效能，是處理子集和問題非常強大的技巧。
## 複雜度分析
### 時間複雜度：
外層迴圈執行 n 次，內層透過 bitset 進行位元運算，整體複雜度約為 O(n*m/64)，能輕鬆在時間限制內完成。
### 空間複雜度：
使用大小為 1800005 的 bitset，僅佔用不到 250 KB 的記憶體空間，空間表現極佳。
## 學習心得
透過這題重新複習了求所有數值組合的動態規劃與優化方法。特別是體會到 bitset 在處理 0/1 狀態轉移時的強大威力，不僅省去了複雜的陣列管理，還能帶來極大的常數優化。
