# 攻防戰
## 題目意思
頂尖駭客小蘋與阿谷正在進行一場網路攻防戰，目標是一個擁有 m 個加密資料節點的伺服器。兩人輪流執行破解程式來刪除節點，但受限於程式的協定，每次只能刪除特定數量的節點。只要有一方無法再根據規定數量刪除節點時，就會被系統的防火牆反追蹤而落敗。這場攻防戰由小蘋率先發動攻擊。

舉例來說，假設伺服器上有 5 個節點，每次規定只能刪除 2 個或 3 個：如果小蘋刪除 2 個，阿谷接下來必定能刪除 3 個，小蘋落敗；如果小蘋刪除 3 個，阿谷必定能刪除 2 個，小蘋還是落敗。因此在這種情況下，小蘋必輸無疑。但如果規定每次只能刪除 3 個或 4 個，伺服器一樣有 5 個節點：小蘋若刪除 3 個，剩下 2 個節點讓阿谷無法執行程式，小蘋獲勝；若小蘋刪除 4 個，剩下 1 個節點阿谷同樣無法動作，小蘋依舊獲勝。此時小蘋必贏。

聰明的小蘋發現，在這場沒有隨機成分且必定會結束的對決中，總有一方擁有「必勝策略」。為了確保自己立於不敗之地，她決定在攻防戰開始前，先利用後門程式偷偷隱藏 x 個節點（x 不得超過伺服器上原有的節點總數），藉此改變初始狀態。假設小蘋與阿谷都能精準算出最佳策略，請問小蘋有幾種選擇非負整數 x 的方法呢？

## 輸入格式
第一行有一個正整數 m，表示伺服器初始擁有 m 個資料節點。
第二行有一個正整數 n，後面接著 n 個以空白隔開的正整數 a1, a2, ..., an，代表每次破解程式允許刪除的節點數量。

## 輸出格式
請輸出一個非負整數，表示有幾種選擇 x 的方式，使得先手的小蘋保證可以獲得勝利。

## 範圍限制
m, n 與所有的 a1 到 an 皆為正整數。

# 攻防戰
## 題目想法
這是一道經典的公平組合遊戲題型。與之前做過的「從頭尾取石頭」的區間 DP 不同，這次是從一個「大池子」裡面取物。雖然形式不同，但兩者的核心精神是一模一樣的：賽局 DP 的本質就是要釐清「目前的視角是自己還是對手」，並且利用「只要能走到對手的必敗態，當下必定為必勝態」的這個邏輯來進行判斷。

## 解題過程
建立一個大小為 m+1 的一維陣列 dp，用來記錄剩下 i 個物品時，當前行動方是否必勝（0 代表必敗，1 代表必勝）。

先將允許取走的數量陣列 A 由小到大排序，方便後續轉移時能優先嘗試較小的消耗，提高提早結束迴圈的機率。

利用外層迴圈遍歷所有可能的狀態大小 i (從 1 到 m)。

內層迴圈枚舉所有合法的取法 A[j]。如果發現取走 A[j] 後的狀態 dp[i - A[j]] 為必敗態 (0)，就代表當前的狀態 i 是必勝態 (1)。

實作上加入優化：一旦確認 dp[i] 為必勝態，就利用 !dp[i] 的條件直接提早中斷內層迴圈，省去不必要的轉移。

最後將迴圈過程中所有的 dp[i] 加總，即為先手必勝的方法數總和。

## 解題方法思考
在設計狀態轉移時，最關鍵的一步在於理解回合與視角的交替。當我們在計算 dp[i] 時，我們看的是走了一步之後的 dp[i - A[j]] 狀態。因為雙方都絕頂聰明，所以只要我們能選擇一種取法，讓剩下的殘局對下一個動作的人（也就是對手）是「必敗」的局面 (!dp[i-A[j]])，那我們這個回合就掌握了「必勝」的策略。

## 複雜度分析
### 時間複雜度：
一開始對陣列 A 進行排序需耗費 O(n log n) 的時間。接著計算 DP 陣列，外層迴圈執行 m 次，內層迴圈最多執行 n 次，最差情況下這部分的複雜度為 O(m * n)。總時間複雜度為 O(m * n + n log n)。

### 空間複雜度：
主要使用了一個大小為 m+1 的 DP 陣列與大小為 n+1 的陣列 A，整體空間複雜度為 O(m + n)。

## 學習心得
這次的題目讓我對賽局 DP 的觀念有更深的體會。比起之前頭尾取石頭的題型，這種單一池子的取物遊戲在狀態定義與實作上更為單純，但也再次驗證了賽局 DP 的核心心法：「判斷自己與對手的視角轉換」。此外，在實作中將可選步數先進行排序，並搭配「找到必勝態就立刻 break」的剪枝機制，是一個在 DP 轉移中非常實用且能大幅減少無效運算的好技巧。
