# 古代礦石
## 題目意思
你是一位星際探險家，在某個遠古遺跡中發現了一排蘊含著龐大能量的古代礦石。為了將這些礦石安全地運送回基地，你必須將它們放入特製的「能量收納匣」中。

每個收納匣可以裝入多顆礦石，但為了避免能量共振引發爆炸，同一個收納匣內的礦石能量值必須維持「嚴格遞增」的狀態。你必須依照礦石原本排列的順序，將它們逐一分發到各個收納匣裡。

由於特製收納匣的造價極為昂貴，請你精算並求出：最少需要準備幾個收納匣，才能將這排古代礦石全部安全打包？
（核心邏輯：給定一個整數序列，求最少能將其劃分為多少個嚴格遞增子序列。）

## 輸入格式
第一行為一個整數 n，代表古代礦石的總數量。
接下來包含 n 個以空格或換行分隔的整數，依序代表這排礦石的能量值。

## 輸出格式
請輸出一個整數，代表最少需要準備的收納匣數量。

## 範圍限制
1 <= n <= 200
所有礦石能量值數據皆在合理範圍，使用標準的 32 位元整數 (int) 型態運算即可，不會產生溢位。

# 古代礦石
## 題目想法
起初看到這題，我直覺的想法是使用貪心策略：每次都從陣列中找出一個最長嚴格遞增子序列 (LIS) 並將其移除，直到所有元素都被取完為止。但仔細推演後，我發現這個策略在某些特定的排列下會失效，不一定能保證切分出「最少」的數量。

## 解題過程
在發現貪心拔除 LIS 的方法不可行後，我查閱了相關資料，這才接觸到數學上的「Dilworth 定理」。這個定理提供了一個非常關鍵的轉換：一個序列要劃分成最少數量的嚴格遞增子序列，其數量剛好會等於該序列的「最長不嚴格遞減子序列 (Longest Non-increasing Subsequence)」的長度。

## 解題方法思考
理解了 Dilworth 定理後，解題方向就變得非常明確。問題從「求最少的劃分數量」轉變成了「求最長不嚴格遞減子序列的長度」。為了讓程式碼實作更簡潔並重複利用熟悉的 LIS 模板，我選擇將輸入的陣列反向讀入。如此一來，原本要求的「最長不嚴格遞減」問題，就巧妙地被轉換成了我們最熟悉的「最長不嚴格遞增 (Non-decreasing)」問題。最後，只要使用 vector 維護陣列，並搭配 upper_bound 進行二分搜尋，就能在高效的時間內找出答案。

## 複雜度分析
### 時間複雜度：
將陣列反轉的成本是 O(N)；接著對長度為 N 的陣列進行 LIS 模板運算，每次尋找插入位置使用 upper_bound 的時間為 O(log N)，因此總時間複雜度為 O(N log N)。

### 空間複雜度：
我們需要一個大小為 N 的陣列來儲存輸入資料，以及一個 tails 的 vector 來維護遞增序列狀態，因此空間複雜度為 O(N)。

## 學習心得
這題給了我很大的啟發。原本直觀覺得需要複雜模擬或貪心切分的問題，竟然能透過 Dilworth 定理進行如此優雅的等價轉換。利用不嚴格 LDS 的特性反向求解最少嚴格遞增子序列數量，不僅數學含義深遠，在實作上也僅需透過反轉陣列並套用熟悉的 LIS 模板就能解決。這次經驗讓我體會到，在演算法解題中，有時候「換個角度看待問題」比埋頭苦幹寫複雜的模擬還要重要得多。
